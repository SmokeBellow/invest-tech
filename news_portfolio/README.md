# Товарный портфель (новостной/фундаментальный) — автоматизация

Перенесён из чата Claude.ai в Claude Code 25.08.2026 (проект вёлся там с
29.06.2026, полный экспорт — `9551db30-portfolioprojectexport.md`, приложен
пользователем при переносе). Раздел 2 `/CLAUDE.md` называл этот портфель
«ведётся вручную в чате, не автоматизируется» — это устарело: с 25.08.2026
он живёт здесь, отдельным сервисом, **не пересекаясь с пайплайном A/B**
(`scripts/`, `data/`, `results/` — технический анализ на дневных барах,
механический GitHub Actions без LLM).

**Ключевое архитектурное отличие от A/B**: у A/B решения — чисто
механические (индикаторы, пороги), поэтому их считает GitHub Actions без
участия LLM (`scripts/live_review.py`). Этот портфель торгуется на
интерпретации новостей и фундаментала — обязательно требует LLM на каждом
пересмотре (различить заголовок от факта, оценить встречный риск,
прочитать новостной поток). Поэтому здесь **нет** механического воркфлоу с
cron — вместо этого ежедневный пересмотр запускает CCR Routine
(`create_trigger`), которая будит ЭТУ агентную сессию (или её продолжение)
по расписанию, сессия сама вызывает MCP-инструменты (FMP, Alpha Vantage,
MetalMiner) и WebSearch, ведёт диалог со своим суждением и коммитит
обновлённое состояние в репозиторий — то же самое, что человек делал
раньше в чате, просто по расписанию и с персистентным состоянием в файлах,
а не в истории чата.

---

## 1. Роль и цель

Полностью автономный виртуальный трейдинг товарными фьючерсами. Решения
принимаются без запроса подтверждения — если позицию нужно закрыть, она
закрывается, с фиксацией в журнале. Реальных денег нет.

**Капитал:** стартовые 100 000 ₽ конвертированы в доллары 13.08.2026 по
курсу ЦБ 82,9977 ₽/$ = **$1 204,85**. С этой даты всё ведётся в долларах,
курс далее не пересчитывается (то же упрощение, что и в A/B — см. `/CLAUDE.md` §3).

**Цель:** максимизировать доходность при просадке от пика не более 20%.

**Учёт P&L:** без плеча и лотности. P&L = % движения цены × выделенный на
позицию капитал. Плечо рассмотрено и отклонено — не увеличивает
доходность при риск-сайзинге, только освобождает кэш, который и так лежит
в SGOV.

## 2. Вотч-лист (11 инструментов)

BR (Brent), GOLD, SILV, NG, ALI, NICK, COPPER, WHEAT (Chicago SRW), COFFEE
(арабика), COCOA, CATTLE (live cattle).

Расширен с исходных 8 до 11 двадцатого августа для диверсификации
драйверов — изначально шесть из восьми инструментов двигались одним
сюжетом (война/перекрытие поставок).

**Карта драйверов:**
- Война/перекрытие поставок (Ормуз, Иран, Чёрное море): BR, ALI, COPPER,
  WHEAT, NICK
- Ставки/ФРС: GOLD, SILV
- Погода в тропиках: COFFEE, COCOA
- Цикл поголовья США: CATTLE
- Газовый баланс США: NG

**Кэш-резерв:** SGOV (iShares 0-3 Month Treasury) — та же логика, что и в
A/B (§3, `/CLAUDE.md`). Не позиция, без стопа/цели.

Живой снимок статусов — `state/watchlist.json`, актуализируется каждым
пересмотром.

  сессии/аккаунта, не отдельный API-ключ**, так что он доступен и здесь
  автоматически, пока сервер подключён к аккаунту. Серверный ключ для
  переноса в GitHub Actions не нужен, т.к. эта автоматизация НЕ идёт через
  Actions (см. врезку выше) — снимает открытый вопрос §12.1 исходного
  экспорта.
- Alpha Vantage: ALUMINUM/COPPER там только на месячных горизонтах —
  бесполезны. NATURAL_GAS дневной есть, но один вызов истории — ~160 000
  токенов, не использовать `return_full_data`.
- Индикаторы (ATR14 для стопов) считать вручную по сырым OHLCV, та же
  дисциплина, что в A/B (`/CLAUDE.md` §4) — не через готовые
  индикаторные эндпоинты с полной историей без ограничения диапазона.
- Kpler (отслеживание судов по AIS) рассмотрен и отклонён — только
  корпоративная подписка, избыточно для виртуального портфеля.
- Проверка на расхождение: при подозрении на пробитие стопа у волатильного
  инструмента — сверять минимум двумя источниками с одинаковой датой (лаг
  MetalMiner в 1-2 дня один раз чуть не привёл к ложному признанию
  стоп-аута, ALI 19-20.08).

## 4. Регламент пересмотра

**Время:** 09:00 Екатеринбург (04:00 UTC), по будням — то же единое время,
что и A/B (`/CLAUDE.md` §1), реализовано как отдельная CCR Routine (не
GitHub Actions cron), см. §7.

**Исключение:** для подтверждённых бинарных макрособытий (решение ФРС,
CPI, PPI, NFP, Джексон-Хоул) — короткий точечный чек ПОСЛЕ публикации в
тот же день, не полный двухуровневый пересмотр. До публикации смотреть
нечего — гадание на прогнозах запрещено правилом выхода по факту (§6,
правило А).

**Два уровня, строгий порядок:**

*Уровень 1 (всегда первым, до любых решений):* полный скан всех 11
инструментов. По каждому: цена за текущую дату + статус тезиса + метка
мимо/наблюдаю/кандидат. Если цена не найдена — писать явно, не
подставлять оценку, не писать «тезис не менялся» вместо цифры. Цель —
поиск идей, не подтверждение уже намеченного плана.

*Уровень 2:* углублённая проработка только кандидатов — структура рынка,
драйверы, встречные риски отдельным пунктом, конкретные параметры входа.

Порядок нельзя нарушать: сначала охват, потом глубина. При нехватке
бюджета — резать глубину проверки открытых позиций (стопы механические,
не пострадают), никогда не резать охват скана.

**Бюджет запросов:** 4-6 на обычный пересмотр, 8-10 в дни крупных событий.
Нет искусственного лимита на число кандидатов — реальные ограничители:
свободные слоты, корреляционные потолки, растянутость цены.

**Формат отчёта в чат:** только Уровень 2 (решения и проработка), не
дублировать полный Уровень 1 скан целиком. Таблица портфеля всегда
включает строку стартового капитала и рост капитала за месяц (% и
абсолют), не только текущий итог и просадку от пика.

## 5. Риск-конструкция

Выведена симуляцией Монте-Карло 60 000 траекторий от барьера просадки 20%
(сделано в чате Claude.ai до переноса — параметры зафиксированы, не
пересчитывать без нового явного запроса пользователя).

- **Риск на сделку: 1,2% портфеля** — математический эквивалент барьера
  просадки 20% при винрейте 40% и R=2,1 (P(просадка>20%)=4,9%).
- **Потолок суммарного открытого риска: 5% портфеля.**
- **Потолок по общему драйверу: 2,5%.** Ключевой вывод симуляции —
  корреляция опаснее размера позиции на порядок: при риске 1,2% на
  позицию P(DD>20%)=2,9% для независимых позиций, но 55-62% для позиций
  на одном сюжете (проверено на военном драйвере).
- **Лимит гэп-экспозиции: не более 30% портфеля в стоимости позиций на
  одном драйвере** — стоп не защищает от разрыва цены на открытии
  (алюминий проседал на 16,2% в один день на новости о сделке). Это
  ограничение ПОВЕРХ риск-лимита, не вместо него.
- **Сайзинг:** размер = (1,2% портфеля) ÷ (дистанция до стопа в %). Стоп
  ставится ПЕРВЫМ по структуре рынка, размер — следствие, никогда не
  наоборот (тот же принцип, что и в A/B, `/CLAUDE.md` §3.4).
- **Стоп по волатильности:** 2×ATR(14) на входе. После входа стоп
  двигается ТОЛЬКО в сторону ужесточения — расширение под давлением цены
  запрещено как принцип.
- **Триггер снижения риска:** просадка 7% от пика → риск падает до 0,8%
  на сделку до нового максимума портфеля.
- **Прочие лимиты:** максимум 25% на позицию, максимум 5 позиций
  одновременно. Требование минимального кэша отменено — кэш это остаток
  между идеями, не целевая доля.

Текущие значения — `state/portfolio.json::risk`.

**Главный вывод исходной симуляции**: при исторической асимметрии
R=0,125 (ранняя стадия проекта) барьер −20% пробивается со 100%
вероятностью при ЛЮБОМ размере риска — размер позиции НЕ лечит
отрицательное матожидание. Приоритет — исправление асимметрии выходов
(правила А/Б, §6), не тонкая настройка сайзинга. См. также §8 (метрика
для оценки процесса).

## 6. Правила выхода и входа

**Правило А — выход только по факту** (введено 29.07 для физических
тезисов, расширено 13.08 на все типы):
- Физический дефицит: выход ТОЛЬКО при фактическом возврате предложения —
  рост биржевых запасов, возобновление отгрузок, перезапуск мощностей. НЕ
  по заголовкам о переговорах/перемирии/сделке.
- Ставочный/макро: выход только при фактическом изменении траектории
  (состоявшееся решение ФРС, вышедшие данные), НЕ при изменении ожиданий.
- Погодный: выход при фактической смене условий, не смене прогноза.
- Общий принцип: заголовок, прогноз, ожидание — не основание для выхода.
  Основание — свершившийся факт, противоречащий тезису.
- Происхождение: SILV закрыт 08.07 на ставочных ОЖИДАНИЯХ — крупнейшая
  ошибка проекта (~1608₽ упущенной прибыли). ALI закрыт 27.07 на
  ЗАГОЛОВКЕ о перемирии, которое развалилось за 4 дня — whipsaw ~70₽.

**Правило Б — трейлинг по 1R** (введено 13.08, заменяет отвергнутую идею
частичной фиксации):
- Выход при откате на величину начального риска (1R) от достигнутого
  максимума прибыли позиции.
- Считается в единицах R, не в процентах.
- Активируется только после того, как позиция прошла +1R прибыли. До
  этого — обычный стоп по структуре.
- Действует вместе со стопом: применяется тот уровень, который жёстче
  (выше).
- Частичная фиксация ОТВЕРГНУТА по результатам симуляции 200k путей:
  «половина на 1R + безубыток» даёт матожидание 0,192R против 0,224R у
  «всё-или-ничего» и 0,253R у трейлинга — поднимает винрейт ценой средней
  прибыли, бьёт ровно в асимметрию R, которую лечим. Не возвращаться без
  новых данных.

**Правило В — срок жизни условия входа:** если заданное условие входа не
сработало 5 торговых сессий подряд И цена ушла более чем на 5% от
заданного коридора — условие автоматически снимается или пересчитывается.
Мёртвые условия не висят.

**Правило Г — конфликт сигналов при недостаточном риск-бюджете:**
формализованного multi-system приоритета нет (это один трейдер, не
несколько систем как в A/B) — приоритет отдаётся кандидатам без
растянутой цены; при избытке кандидатов часть переносится на следующую
сессию явно, не молча.

**Мёртвый капитал:** позиция, стоящая у входа неделями без движения,
может закрываться как неработающий капитал — кэш в SGOV хотя бы
накапливает процент.

## 7. Автоматизация (реализовано 25.08.2026)

**Механизм: CCR Routine** (`create_trigger`/`mcp__...__create_trigger`),
НЕ GitHub Actions — обоснование в врезке в начале файла. Routine будит эту
агентную сессию по будням в 09:00 Екатеринбург (04:00 UTC), сессия:

1. Читает текущее состояние — `state/portfolio.json`,
   `state/positions.json`, `state/watchlist.json`.
2. Проводит Уровень 1 (скан всех 11 инструментов через MCP/WebSearch,
   §3-4).
3. Для кандидатов — Уровень 2 (углублённая проработка).
4. Проверяет открытые позиции: обновляет стопы (только в сторону
   ужесточения), проверяет трейлинг-1R, применяет правила А/Б/В/Г.
5. Исполняет решения — записывает entry/exit в `state/journal.csv`,
   обновляет `state/positions.json` и `state/portfolio.json` (equity,
   peak, realized P&L, просадка).
6. Коммитит и пушит обновлённые файлы в `state/` в ветку.
7. Публикует краткий отчёт (Уровень 2 + таблица портфеля) как сообщение в
   этой же сессии — формат см. §4.

Точечные чеки после макрособытий (FOMC/CPI/PPI/NFP/Джексон-Хоул) — заведены
как отдельные one-shot напоминания (`send_later`) на дату/время события,
не часть регулярной Routine.

**Персистентность состояния** — снимает открытый вопрос §12.3 исходного
экспорта: `state/*.json`/`.csv` читаются/пишутся как файлы репозитория при
каждом запуске, не хранятся в промпте/истории чата.

**Routine создана 25.08.2026**, `trigger_id: trig_01PvPrzZNFYH9eRQNMSS5x8h`,
cron `0 4 * * 1-5` (UTC), само-привязана к текущей агентной сессии
(`persist_session=true` — та же сессия, что вела перенос из чата).

**Известный риск, не проверенный на практике**: API создания Routine
вернула предупреждение, что явный список MCP-коннекторов (`connectors`)
для этой организации не поддерживается — при само-привязке к
существующей сессии (не при спавне новой) коннекторы (Alpha Vantage MCP,
FMP, MetalMiner — все три включены в этой сессии на момент создания)
должны сохраниться просто потому, что это буквально та же сессия, а не
новый инстанс без истории подключений — но это не подтверждено первым
реальным срабатыванием. Если при первом пересмотре (26.08.2026) MCP-
инструменты окажутся недоступны — пересоздать Routine из интерфейса
claude.ai (там коннекторы настраиваются вручную при создании), не
додумывать обходной путь молча.

## 8. Метрика для оценки процесса

Критерий (задан 13.08 в чате): к середине сентября 2026 средняя
прибыльная сделка должна быть не меньше средней убыточной (исправление
исторической асимметрии R≈0,125). Если сохранится — проблема структурная,
требует пересмотра логики выхода, а не только сайзинга.

Отчёт по точности решений на 13.08.2026 (охватывал 29.06-13.08): 15
решений, 11 верных (73%), но взвешенный вклад отрицательный — верные
решения были мелкими (невходы), ошибочные крупными (выход из SILV на
ожиданиях). За полтора месяца портфель на тот момент отставал от простой
парковки в TMON — пересчитать этот же тест на данных по 25.08 при
следующей контрольной точке (не сделано при переносе — открытый вопрос,
см. §9).

## 9. Открытые вопросы (перенесены из экспорта, НЕ додумывать)

1. WHEAT/COFFEE/COCOA/CATTLE — нет надёжного бесплатного API, полагаемся
   на WebSearch. Проверить качество на практике за первые недели работы
   Routine; при частых пропусках рассмотреть платный Commodities-API
   (~$16/мес) — решение пользователя, не автоматически.
2. Пересчёт метрики точности решений (§8) на данных по 25.08 — не сделан
   при переносе, следующая контрольная точка — середина сентября 2026.
3. Точная цифра выхода ALI-2 (стоп 20-21.08) расходится в источниках чата
   (−$4 vs небольшой плюс) из-за смены референсных цен LME/TradingEconomics/
   MetalMiner в течение проекта — `state/journal.csv` несёт то же
   расхождение как явный комментарий, пересчитывать с нуля по единому
   источнику только если точность станет критичной для пользователя.
4. Формат/периодичность будущих отчётов (в чат vs только в файлы) —
   пользователь ранее упоминал переход A/B-отчётов с ежедневных на
   еженедельные (`/CLAUDE.md` §9) — для этого портфеля периодичность не
   зафиксирована отдельно, по умолчанию ежедневно как раньше в чате, до
   явного запроса на снижение частоты.
